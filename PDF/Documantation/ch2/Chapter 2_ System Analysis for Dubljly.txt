2 System Analysis

This chapter analyzes the Dubljly system, which transforms English educational videos into Arabic-dubbed content for Jordanian students. It details data flow, user requirements, system components, and solution options, adhering to the Yarmouk University Department of Computer Information Systems guidelines [1]. The system addresses language barriers in education, as outlined in Chapter 1 [2].

2.1 Data Analysis

The Dubljly system processes YouTube videos into Arabic-dubbed videos, summaries, keywords, chatbot responses, and transcripts. The pipeline, based on [3, 4], includes nine steps:
1. User submits a YouTube URL.
2. System checks URL validity (True/False).
3. If True, download video and extract audio.
4. Perform Speech-to-Text (STT) transcription.
5. Use Large Language Model (LLM) to generate summary, keywords, chatbot Q&A, and transcript.
6. Generate Text-to-Speech (TTS) audio.
7. Check speech timing against video duration.
8. Merge audio with video.
9. Deliver dubbed video to user.

2.1.2.1 Clients, Customers, and Users
- Students: Arabic-speaking learners (e.g., Jordanian high school/university students) submitting YouTube URLs for dubbed videos, summaries, keywords, and chatbot Q&A [5].
- Educators: Teachers uploading videos for classroom use, needing simple access to dubbed content.
- Administrators: IT staff managing system operations and API endpoints.

2.1.2.2 Functional and Data Requirements
Functional Requirements:
1. Validate YouTube URL format via `/api/video/` endpoint [6].
2. Download MP4 video using `yt_dlp` if URL is valid [3].
3. Extract WAV audio with FFmpeg [3].
4. Transcribe audio to English text with FastWhisper [3].
5. Generate Arabic translation, summary, keywords, and Q&A with Groq API [7].
6. Synthesize Arabic audio with XTTS-v2 [4].
7. Verify audio timing matches video duration [4].
8. Merge audio and video into MP4 with FFmpeg [4].
9. Deliver dubbed video via web interface or `/tts-api/generate-dubbed-video/<video_id>/` [6].

Data Requirements:
- Input: YouTube URL (string, validated), MP4 video (up to 2 hours).
- Processed: WAV audio, English transcript (text), Arabic translation (text), summary (text), keywords (list), Q&A (JSON), Arabic audio (WAV).
- Output: Dubbed MP4 video, JSON API responses (metadata, chatbot answers).
- Storage: SQLite database with `Video` and `Transcript` models, file system at `/media/videos/` [8, 9].

2.1.2.3 Non-functional Requirements
- Usability: Arabic-language web interface with clear buttons (e.g., “ابدأ الدبلجة”), minimal user steps [10].
- Performance: Process a 10-minute video in 2–5 minutes on a PC with i5 CPU and 8GB RAM [10].
- Security: Require API key for `/api/video/` and `/tts-api/` endpoints, delete temporary files after processing [9].
- Accessibility: Support right-to-left Arabic text, mobile-responsive design [10].
- Reliability: Achieve 95% success rate for valid URLs, display Arabic error messages for invalid inputs [7].

2.1.4 Proposed Solutions

The Dubljly system processes videos through a 9-step pipeline [3, 4]:
1. User submits a YouTube URL via the web interface or `/api/video/` [6].
2. System validates the URL using `yt_dlp`; if False, display error; if True, proceed [3].
3. Download MP4 video and extract WAV audio with FFmpeg [3].
4. Transcribe audio to English text with FastWhisper [3].
5. Use Groq API to generate Arabic translation, summary, keywords, and Q&A [7].
6. Synthesize Arabic audio with XTTS-v2 [4].
7. Check audio duration matches video timing [4].
8. Merge audio and video into MP4 with FFmpeg [4].
9. Deliver dubbed video via web interface or `/tts-api/generate-dubbed-video/<video_id>/` [6].

Tool selections were based on performance evaluations:
- `yt_dlp` outperforms `pytube` in download speed [3].
- FastWhisper is faster and more accurate than OpenAI Whisper [3].
- Groq API produces natural Arabic translations [7].
- XTTS-v2 offers high-quality Arabic audio [4].

The system uses a Django web application, running on Windows 11 with cloud-based LLM processing via Groq API [10].

2.1.5 Alternative Solutions

Three alternative approaches were considered:
- Cloud-Based Processing: Using Google STT and AWS Polly offers scalability but incurs high costs and requires constant internet [3].
- Subtitle-Only Solution: Generating Arabic subtitles is faster but less immersive for students [2].
- Human Dubbing: Professional dubbing provides high-quality audio but costs $2,000 per hour and takes weeks [2].

Dubljly’s hybrid solution (local processing with cloud LLM) is cost-effective and suitable for Jordanian educational institutions [5].
