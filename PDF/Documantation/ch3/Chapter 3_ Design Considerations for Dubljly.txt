3 Design Considerations

This chapter details the design considerations for the Dubljly system, which dubs English educational videos into Arabic for Jordanian students. It covers system architecture, constraints, user interface, implementation details, performance, and security, adhering to the Yarmouk University Department of Computer Information Systems guidelines [1]. The design supports the 9-step pipeline outlined in Chapter 2 [2] and addresses educational needs in Jordan, as identified in Chapter 1 [13].

3.1 Design Overview

The Dubljly system is a Django 4.2.7 web application that processes YouTube videos through a 9-step pipeline: (1) Video URL input, (2) Check URL validity, (3) Download video and extract audio, (4) Speech-to-Text (STT), (5) Large Language Model (LLM) processing for summary, keywords, chatbot Q&A, and transcript, (6) Text-to-Speech (TTS), (7) Check speech timing, (8) Merge audio with video, (9) Deliver dubbed video [3, 4]. It combines local processing on Windows 11 Home with cloud-based LLM services via Groq API (Qwen-qwq-32B model) to optimize cost and performance [10].

System Architecture Diagram:
- Components: User Interface (Django front-end), Processing Modules (STT, LLM, TTS), SQLite Database (Video, Transcript models), File System (/media/videos/), Groq API (cloud).
- Interactions: User submits URL via UI → Processing Modules execute pipeline → Database stores metadata and transcripts → File System saves videos → Groq API handles LLM tasks → User receives dubbed video.

The architecture ensures modularity, with Django managing user interactions, processing modules handling pipeline steps, and SQLite storing data efficiently [6, 8, 9]. The Groq API offloads compute-intensive LLM tasks, reducing local hardware demands [7, 10].

3.2 Design Constraints

The system’s design adheres to hardware, software, and user constraints specified in [10], ensuring affordability and accessibility for Jordanian schools.

3.2.1 Hardware Constraints
- Processor: Intel i5-10400 (6 cores, 2.9 GHz) or equivalent [10].
- Memory: 8GB DDR4 RAM (minimum for multitasking) [10].
- Storage: 256GB SSD with 10GB free space for videos, audio, and SQLite database [9, 10].
- Operating System: Windows 11 Home (build 23H2) for compatibility with Python and Django [10].
- Connectivity: Broadband internet (5 Mbps minimum) for YouTube downloads and Groq API calls [7, 10].
- Budget: Hardware cost not to exceed $500 to support deployment in resource-constrained schools [10].

These constraints ensure the system runs on mid-range PCs available in Jordanian educational institutions [5].

3.2.2 Software Constraints
- Programming Language: Python 3.9.7 for scripting and Django integration [10].
- Framework: Django 4.2.7 with Django REST Framework 3.14.0 for web app and API [6].
- Database: SQLite 3.36 for lightweight, local storage [8, 10].
- Processing Tools:
  - `yt_dlp` (v2023.12.30) for URL validation and video download [3].
  - FFmpeg (v6.0) for audio extraction (WAV) and video merging (MP4) [3].
  - FastWhisper (v0.2.0) for STT with medium.en model [3].
  - XTTS-v2 (v2.0.2) for TTS with Arabic voice support [4].
- Cloud API: Groq API with Qwen-qwq-32B model (50 requests/min limit, 99.9% uptime) [7, 10].
- Compatibility: All tools must run on Windows 11, with dependencies managed via pip [10].
- Licensing: Open-source tools to minimize costs, with Groq API on free tier for prototyping [10].

These choices balance performance and cost, leveraging open-source software for scalability [10].

3.2.3 User Constraints
- Primary Users: Arabic-speaking students (ages 12–22, K-12 and university), educators, and administrators [5, 10].
- Technical Skills:
  - Students: Basic computer literacy (e.g., browser navigation, file downloads) [10].
  - Educators: Minimal tech skills, requiring intuitive interfaces [10].
  - Administrators: Proficient in API management and database maintenance [10].
- Language: Arabic (Modern Standard Arabic) with right-to-left text support [10].
- Accessibility Needs: Mobile access (responsive design), high-contrast UI, WCAG 2.1 Level AA compliance (e.g., 4.5:1 contrast ratio) [10].
- Cultural Context: Interface reflects Jordanian educational norms (e.g., formal Arabic, educational terminology) [5].

The design prioritizes simplicity for students and educators while supporting administrative tasks [10].

3.3 User Interface Design

The user interface is a Django-based web application with an Arabic front-end, optimized for usability and accessibility [10].

- Layout: Single-page design with:
  - URL input field (placeholder: “أدخل رابط يوتيوب”).
  - “ابدأ الدبلجة” (Start Dubbing) button (blue, 16pt font).
  - Progress bar (0–100%) showing pipeline status.
  - Output section for dubbed video (MP4 download link), summary, keywords, and chatbot [10].
- Features by User Role:
  - Students: Submit URL, view dubbed video, access summary/keywords, interact with chatbot via `/api/videos/<id>/ask/` [6, 10].
  - Educators: Upload multiple URLs (up to 5 simultaneously), download dubbed videos as ZIP [6, 10].
  - Administrators: Dashboard for monitoring pipeline status, managing API keys, and viewing logs [10].
- Navigation: Maximum 3 clicks to complete tasks (e.g., URL submission to video download) [10].
- Accessibility:
  - Right-to-left Arabic text using Noto Sans Arabic font [10].
  - Mobile-responsive design (Bootstrap 5.3 for layout) [10].
  - High-contrast colors (e.g., blue buttons on white background) [10].
  - ARIA labels for screen readers (e.g., “URL input field”) [10].
- Error Handling: Arabic error messages (e.g., “رابط غير صحيح” for invalid URL, “حاول مجدداً” for API errors) [7, 10].

3.4 Implementation Considerations

The system’s implementation uses specific tools, APIs, and database designs to execute the pipeline efficiently [3, 4].

3.4.1 Tool Selection
- URL Validation/Download: `yt_dlp` (v2023.12.30) validates URLs and downloads MP4 videos (up to 1080p), outperforming `pytube` in speed (2x faster) and error handling [3, 10].
- Audio Extraction: FFmpeg (v6.0) extracts WAV audio (44.1 kHz, mono) for STT and merges MP4 videos, chosen for reliability [3, 10].
- STT: FastWhisper (v0.2.0, medium.en model) transcribes audio with 95% accuracy, 30% faster than OpenAI Whisper [3, 10].
- LLM: Groq API (Qwen-qwq-32B) generates Arabic translations (BLEU score 0.85), summaries (200 words), keywords (10 per video), and Q&A (JSON format), with 50 requests/min limit [7, 10].
- TTS: XTTS-v2 (v2.0.2) synthesizes Arabic audio (female voice, 22 kHz) with silence removal (<0.5s gaps), outperforming Tacotron2 [4, 10].
- Timing Check: Custom Python script (`Sayyid_work_TTS.py`) compares audio and video durations (±5% tolerance) [4, 10].
- Video Merging: FFmpeg synchronizes audio and video with 99% frame accuracy [4, 10].

3.4.2 API Integration
- Endpoints:
  - `/api/video/` (POST): Submits URL, returns video ID [6].
  - `/tts-api/generate-dubbed-video/<video_id>/` (GET): Retrieves dubbed MP4 [6].
  - `/api/videos/<id>/ask/` (POST): Submits questions, returns Q&A [6].
- Authentication: API keys (32-character UUID) in HTTP headers, configured in `settings.py` [9, 10].
- Rate Limiting: 100 requests/hour per user to prevent abuse [10].
- Error Handling: 3 retries for Groq API timeouts (5s interval), Arabic error messages [7, 10].

3.4.3 Database Design
- Models:
  - `Video`: Fields (id: AutoField, url: CharField(max_length=200), title: CharField(max_length=100), generated_video_url: CharField(max_length=200)), Methods (save()) [8].
  - `Transcript`: Fields (video: OneToOneField(Video), content: TextField, timestamps: JSONField), Methods (save()) [8].
- Storage: SQLite 3.36 database (dubljly.db, <100MB), file system (/media/videos/, <10GB) [9, 10].
- Indexing: Index on `Video.url` for fast lookups [10].
- Backup: Daily database snapshots to /backups/ [10].

The implementation separates concerns, with modular scripts (`STT.py`, `LLM_Online.py`, `Sayyid_work_TTS.py`) for each pipeline step [11, 7, 4].

3.5 Performance and Security

3.5.1 Performance
- Processing Time: 2–5 minutes for a 10-minute video (i5-10400, 8GB RAM), with breakdown:
  - Download: 30s (5 Mbps internet) [3].
  - STT: 45s (FastWhisper) [3].
  - LLM: 20s (Groq API) [7].
  - TTS: 60s (XTTS-v2) [4].
  - Merging: 25s (FFmpeg) [4].
- Throughput: One video at a time, with queue system for multiple submissions [10].
- Optimization: FastWhisper’s batch processing, XTTS-v2’s GPU acceleration (if NVIDIA GTX 1650 available) [3, 4, 10].
- Error Handling: Invalid URLs return “رابط غير صحيح” within 2s; API failures trigger retries [7, 10].
- Reliability: 95% success rate for valid URLs, tested on 100 videos [10].

3.5.2 Security
- Data Privacy: Temporary WAV/MP4 files deleted within 1 hour of processing [10].
- API Security: HTTPS (TLS 1.3) for all endpoints, API key authentication [9, 10].
- Input Validation: URLs sanitized to prevent injection attacks [3, 10].
- Compliance: Adheres to YouTube’s API terms and Jordanian data protection laws [10].
- Logging: All API calls logged (timestamp, endpoint, status) to /logs/ [10].
