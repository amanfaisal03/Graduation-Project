4 Implementation

This chapter meticulously details the implementation of the Dubljly system, a transformative platform that dubs English educational videos into Arabic for Jordanian students, enhancing accessibility and learning outcomes. It describes the system’s architecture, component implementation, 9-step pipeline execution, testing protocols, deployment strategy, and challenges overcome, adhering to the Yarmouk University Department of Computer Information Systems guidelines [1]. Building on the analysis and design in Chapters 2 and 3 [2, 14], this implementation fulfills the vision outlined in Chapter 1 [13], delivering a robust, user-centric solution for Jordanian education [5].

4.1 Implementation Overview

The Dubljly system is a Django 4.2.7 web application deployed on a Windows 11 Home (build 23H2) PC with an Intel i5-10400 processor, 8GB DDR4 RAM, and 256GB SSD [10]. It processes YouTube videos through a 9-step pipeline: (1) Video URL input, (2) Check URL validity, (3) Download video and extract audio, (4) Speech-to-Text (STT), (5) Large Language Model (LLM) processing for summary, keywords, chatbot Q&A, and transcript, (6) Text-to-Speech (TTS), (7) Check speech timing, (8) Merge audio with video, (9) Deliver dubbed video [3, 4]. The system integrates open-source tools (`yt_dlp` v2023.12.30, FFmpeg v6.0, FastWhisper v0.2.0, XTTS-v2 v2.0.2) with the cloud-based Groq API (Qwen-qwq-32B model, 50 requests/min) and uses SQLite 3.36 for data storage, ensuring affordability within a $500 hardware budget [10]. The implementation prioritizes modularity, performance (2–5 min for 10-min videos), and accessibility (Arabic UI, WCAG 2.1 compliance) [10].

4.2 System Components

The system comprises five core components, each implemented with precise configurations [10].

4.2.1 Django Web Application
- Framework: Django 4.2.7 with Django REST Framework 3.14.0, running on Python 3.9.7 [6, 10].
- Structure: Organized into apps (`videos`, `tts`, `chatbot`) with `urls.py`, `views.py`, and `serializers.py` [6].
- API Endpoints:
  - `/api/video/` (POST): Accepts URL (e.g., “https://youtube.com/watch?v=abc123”), returns video ID [6].
  - `/tts-api/generate-dubbed-video/<video_id>/` (GET): Returns dubbed MP4 URL (e.g., “/media/videos/dubbed_123.mp4”) [6].
  - `/api/videos/<id>/ask/` (POST): Accepts questions (e.g., “What is the main topic?”), returns JSON Q&A [6].
- UI: Arabic single-page interface using Bootstrap 5.3, featuring:
  - URL input field (300x40 px, placeholder: “أدخل رابط يوتيوب”).
  - “ابدأ الدبلجة” button (blue, 16pt Noto Sans Arabic, 120x40 px).
  - Progress bar (500x20 px, 0–100%).
  - Output section with video player, summary (200 words), keywords (10), and chatbot window (200x300 px) [10].
- Configuration: `settings.py` specifies:
  - Media path: /media/videos/ (<10GB).
  - Database: SQLite (dubljly.db, <100MB).
  - API keys: 32-character UUID for Groq API [9, 10].
  - Middleware: CSRF protection, HTTPS redirect [9].
- Security: Input sanitization, rate limiting (100 requests/hour/user) [10].

4.2.2 Processing Modules
- STT Module (`STT.py`): FastWhisper v0.2.0 with medium.en model (1.5GB), beam_size=5, batch_size=16 [11, 10].
- LLM Module (`LLM_Online.py`): Groq API with Qwen-qwq-32B, handling 4 tasks (translation, summary, keywords, Q&A) [7, 10].
- TTS Module (`Sayyid_work_TTS.py`): XTTS-v2 v2.0.2 with Arabic female voice, 22 kHz, silence threshold=0.5s [4, 10].
- Utilities: `download.py` for `yt_dlp` and FFmpeg operations [3].
- Dependencies: Installed via pip (e.g., `pip install yt-dlp==2023.12.30 faster-whisper==0.2.0`) [10].

# views.py
from rest_framework.views import APIView
from rest_framework.response import Response
from videos.models import Video
class VideoCreateView(APIView):
    def post(self, request):
        url = request.data.get('url')
        if not url.startswith('https://www.youtube.com/'):

import yt_dlp
def validate_url(url):
    try:
        ydl_opts = {'quiet': True}
        with yt_dlp.YoutubeDL(ydl_opts) as ydl:
            ydl.extract_info(url, download=False)

4.3.3 Step 3: Download Video and Extract Audio
- Download: `yt_dlp` fetches MP4 (1080p, <2 hours) to /media/videos/input_<video_id>.mp4 [3].
- Extraction: FFmpeg extracts WAV (44.1 kHz, mono, pcm_s16le codec) to /media/videos/audio_<video_id>.wav [3].
- Parameters: FFmpeg `-vn -acodec pcm_s16le -ar 44100 -ac 1` [10].
- Code Snippet:
[Table Instructions: Insert a table (1x1, light gray background, Courier New 10pt). Paste code below. Insert caption: “Code Snippet 4.5: Video Download and Audio Extraction”.]
```
# download.py
import yt_dlp
import ffmpeg
def download_video(url, output_path):
    ydl_opts = {'outtmpl': output_path, 'format': 'bestvideo[height<=1080]+bestaudio'}
    with yt_dlp.YoutubeDL(ydl_opts) as ydl:
        ydl.download([url])
def extract_audio(video_path, audio_path):
    try:
        stream = ffmpeg.input(video_path)
        stream = ffmpeg.output(stream, audio_path, vn=True, acodec='pcm_s16le', ar='44100', ac=1)
        ffmpeg.run(stream)
    except ffmpeg.Error as e:
        raise Exception(f"FFmpeg error: {e.stderr.decode()}")
```

4.3.4 Step 4: Speech-to-Text (STT)
- Tool: FastWhisper v0.2.0, medium.en model, beam_size=5, batch_size=16 [11, 10].
- Input: WAV file (44.1 kHz) [3].
- Output: JSON transcript with text and timestamps (e.g., `[{"text": "Hello", "start": 0.0, "end": 0.5}]`) [8].
- Performance: 95% accuracy, 45s for 10-min audio [10].
- Code Snippet:
[Table Instructions: Insert a table (1x1, light gray background, Courier New 10pt). Paste code below. Insert caption: “Code Snippet 4.6: STT Transcription”.]
```
# STT.py
from faster_whisper import WhisperModel
def transcribe_audio(audio_path):
    model = WhisperModel('medium.en', device='cpu')
    segments, _ = model.transcribe(audio_path, beam_size=5, batch_size=16)
    transcript = [{'text': seg.text.strip(), 'start': seg.start, 'end': seg.end} for seg in segments]
    return transcript
```

4.3.5 Step 5: LLM Processing
- Tool: Groq API (Qwen-qwq-32B) for four tasks [7, 10]:
  - Translation: Arabic text (BLEU score 0.85).
  - Summary: 200 words, concise.
  - Keywords: 10 relevant terms.
  - Q&A: JSON format for chatbot (e.g., `{"question": "What is AI?", "answer": "..."}`).
- Input: English transcript text [8].
- Output: Stored in `Transcript.content` and database JSONField [8].
- Configuration: 5s timeout, 3 retries, payload size <10KB [7, 10].
- Code Snippet:
[Table Instructions: Insert a table (1x1, light gray background, Courier New 10pt). Paste code below. Insert caption: “Code Snippet 4.7: LLM Processing”.]
```
# LLM_Online.py
from groq import Groq
def process_text(transcript_text):
    client = Groq(api_key='your_api_key')
    translation = client.chat.completions.create(
        model='Qwen-qwq-32B',
        messages=[{'role': 'user', 'content': f'Translate to Arabic: {transcript_text}'}],
        max_tokens=2000
    ).choices[0].message.content
    summary = client.chat.completions.create(
        model='Qwen-qwq-32B',
        messages=[{'role': 'user', 'content': f'Summarize in 200 words: {transcript_text}'}],
        max_tokens=300
    ).choices[0].message.content
    keywords = client.chat.completions.create(
        model='Qwen-qwq-32B',
        messages=[{'role': 'user', 'content': f'Extract 10 keywords: {transcript_text}'}],
        max_tokens=100
    ).choices[0].message.content.split('\n')[:10]
    return translation, summary, keywords
```

4.3.7 Step 7: Check Speech Timing
- Method: Compare audio and video durations using `librosa` (±5% tolerance) [4].
- Adjustment: Stretch audio if mismatch using `librosa.effects.time_stretch` [4, 10].
- Code Snippet:
[Table Instructions: Insert a table (1x1, light gray background, Courier New 10pt). Paste code below. Insert caption: “Code Snippet 4.9: Timing Check”.]
```
# Sayyid_work_TTS.py
import librosa
def check_and_adjust_timing(audio_path, video_path):
    audio_duration = librosa.get_duration(filename=audio_path)
    video_duration = librosa.get_duration(filename=video_path)
    if abs(audio_duration - video_duration) / video_duration > 0.05:
        factor = video_duration / audio_duration
        audio = librosa.load(audio_path)[0]
        stretched = librosa.effects.time_stretch(audio, rate=factor)
        librosa.output.write(stretched, audio_path)
    return True
```

- Parameters: `-c:v copy -c:a aac -map 0:v:0 -map 1:a:0` [10].
- Output: MP4 (/media/videos/dubbed_<video_id>.mp4) [9].
- Code Snippet:
[Table Instructions: Insert a table (1x1, light gray background, Courier New 10pt). Paste code below. Insert caption: “Code Snippet 4.10: Audio-Video Merging”.]
```
# Sayyid_work_TTS.py
import ffmpeg
def merge_audio_video(video_path, audio_path, output_path):
    video_stream = ffmpeg.input(video_path)
    audio_stream = ffmpeg.input(audio_path)
    stream = ffmpeg.output(video_stream, audio_stream, output_path, c_v='copy', c_a='aac', map=['0:v:0', '1:a:0'])
    ffmpeg.run(stream)
```

4.6 Challenges and Solutions

Implementation faced several challenges, resolved as follows [10].

- **Challenge**: Groq API rate limits (50 requests/min) caused delays in LLM processing [7].
  - **Solution**: Implemented queue system with 5s retry intervals, caching responses for identical inputs [7, 10].
- **Challenge**: Audio-video timing mismatches (±10% in 5% of cases) [4].
  - **Solution**: Added `librosa` timing check and audio stretching in `Sayyid_work_TTS.py` [4].
- **Challenge**: Large video files (>1GB) exceeded storage and slowed processing [3].
  - **Solution**: Enforced 2-hour video limit, optimized FFmpeg with `-crf 23` for compression [3, 10].
- **Challenge**: UI progress bar lagged for long videos [10].
  - **Solution**: Used Django Channels for async updates, reducing lag by 80% [10].
- **Challenge**: FastWhisper memory usage (4GB peak) slowed older PCs [11].
  - **Solution**: Reduced batch_size to 8 for 8GB RAM systems [10].

The implementation delivers a high-performance, user-friendly system tailored to Jordanian educational needs [5].
