4 Implementation

This chapter describes the implementation of the Dubljly system, which dubs English educational videos into Arabic for Jordanian students. It details the system’s components, the 9-step pipeline implementation, testing methods, and challenges, adhering to the Yarmouk University Department of Computer Information Systems guidelines [1]. The implementation builds on the system analysis and design from Chapters 2 and 3 [2, 14], addressing educational needs outlined in Chapter 1 [13].

4.1 Implementation Overview

The Dubljly system is a Django 4.2.7 web application deployed on Windows 11 Home, integrating local processing with cloud-based Groq API (Qwen-qwq-32B model) [10]. It executes a 9-step pipeline: (1) Video URL input, (2) Check URL validity, (3) Download video and extract audio, (4) Speech-to-Text (STT), (5) Large Language Model (LLM) processing for summary, keywords, chatbot Q&A, and transcript, (6) Text-to-Speech (TTS), (7) Check speech timing, (8) Merge audio with video, (9) Deliver dubbed video [3, 4]. The system uses open-source tools (`yt_dlp`, FFmpeg, FastWhisper, XTTS-v2) and a SQLite 3.36 database, ensuring affordability for Jordanian schools [5, 10].

4.2 System Components

The system comprises five main components, implemented as follows [10].

4.2.1 Django Web Application
- Framework: Django 4.2.7 with Django REST Framework 3.14.0 [6].
- Endpoints:
  - `/api/video/` (POST): Accepts YouTube URL, returns video ID [6].
  - `/tts-api/generate-dubbed-video/<video_id>/` (GET): Returns dubbed MP4 URL [6].
  - `/api/videos/<id>/ask/` (POST): Handles chatbot Q&A [6].
- UI: Arabic single-page interface with URL input, “ابدأ الدبلجة” button, progress bar, and output section (video, summary, keywords, chatbot) [10].
- Configuration: `settings.py` defines API keys, media paths (/media/videos/), and SQLite database (dubljly.db) [9].

4.2.2 Processing Modules
- STT Module (`STT.py`): Uses FastWhisper v0.2.0 (medium.en model) for transcription [11].
- LLM Module (`LLM_Online.py`): Integrates Groq API for translation, summary, keywords, and Q&A [7].
- TTS Module (`Sayyid_work_TTS.py`): Employs XTTS-v2 v2.0.2 for Arabic audio synthesis [4].
- Dependencies: Python 3.9.7, `yt_dlp` v2023.12.30, FFmpeg v6.0 [3, 10].

4.2.3 SQLite Database
- Models: `Video` (id, url, title, generated_video_url), `Transcript` (video, content, timestamps) [8].
- Schema: One-to-one relationship between `Video` and `Transcript`, indexed on `Video.url` [8, 10].
- Size: <100MB, stored at /db/dubljly.db [9].

4.2.4 File System
- Path: /media/videos/ for MP4 and WAV files (<10GB) [9].
- Management: Temporary files deleted within 1 hour [10].

4.2.5 Groq API
- Model: Qwen-qwq-32B for LLM tasks [7].
- Limits: 50 requests/min, configured in `LLM_Online.py` [7, 10].

4.3.2 Step 2: Check URL Validity
- Tool: `yt_dlp` v2023.12.30 validates URL format and accessibility [3].
- Output: True (valid) proceeds; False returns “رابط غير صحيح” [7, 10].

4.3.3 Step 3: Download Video and Extract Audio
- Download: `yt_dlp` fetches MP4 (1080p max) to /media/videos/ [3].
- Extraction: FFmpeg v6.0 converts MP4 to WAV (44.1 kHz, mono) [3].
- Code Snippet:
[Table Instructions: Insert a table (1x1, light gray background, Courier New 10pt). Paste code below. Insert caption: “Code Snippet 4.2: Video Download and Audio Extraction”.]
```
# download.py
import yt_dlp
import ffmpeg
def download_video(url, output_path):
    ydl_opts = {'outtmpl': output_path}
    with yt_dlp.YoutubeDL(ydl_opts) as ydl:
        ydl.download([url])
def extract_audio(video_path, audio_path):
    stream = ffmpeg.input(video_path)
    stream = ffmpeg.output(stream, audio_path, acodec='pcm_s16le', ar='44100')
    ffmpeg.run(stream)
```

4.3.4 Step 4: Speech-to-Text (STT)
- Tool: FastWhisper v0.2.0 (medium.en model) transcribes WAV to text [11].
- Output: English transcript with timestamps, stored in `Transcript.content` [8].
- Code Snippet:
[Table Instructions: Insert a table (1x1, light gray background, Courier New 10pt). Paste code below. Insert caption: “Code Snippet 4.3: STT Transcription”.]
```
# STT.py
from faster_whisper import WhisperModel
def transcribe_audio(audio_path):
    model = WhisperModel('medium.en')
    segments, _ = model.transcribe(audio_path)
    transcript = [{'text': seg.text, 'start': seg.start} for seg in segments]
    return transcript
```

4.3.5 Step 5: LLM Processing
- Tool: Groq API (Qwen-qwq-32B) generates Arabic translation, 200-word summary, 10 keywords, and Q&A [7].
- Output: Stored in database and returned via `/api/videos/<id>/ask/` [6, 8].
- Code Snippet:
[Table Instructions: Insert a table (1x1, light gray background, Courier New 10pt). Paste code below. Insert caption: “Code Snippet 4.4: LLM Processing”.]
```
# LLM_Online.py
from groq import Groq
client = Groq(api_key='your_api_key')
def process_text(transcript):
    translation = client.chat.completions.create(
        model='Qwen-qwq-32B', messages=[{'role': 'user', 'content': f'Translate: {transcript}'}]
    ).choices[0].message.content
    summary = client.chat.completions.create(
        model='Qwen-qwq-32B', messages=[{'role': 'user', 'content': f'Summarize in 200 words: {transcript}'}]
    ).choices[0].message.content
    return translation, summary
```

4.3.6 Step 6: Text-to-Speech (TTS)
- Tool: XTTS-v2 v2.0.2 synthesizes Arabic audio (female voice, 22 kHz) [4].
- Output: WAV file with silence removal (<0.5s gaps) [4].

4.3.7 Step 7: Check Speech Timing
- Implementation: Custom script compares audio and video durations (±5% tolerance) [4].
- Code Snippet:
[Table Instructions: Insert a table (1x1, light gray background, Courier New 10pt). Paste code below. Insert caption: “Code Snippet 4.5: Timing Check”.]
```
# Sayyid_work_TTS.py
import librosa
def check_timing(audio_path, video_path):
    audio_duration = librosa.get_duration(filename=audio_path)
    video_duration = librosa.get_duration(filename=video_path)
    return abs(audio_duration - video_duration) / video_duration <= 0.05
```

4.3.8 Step 8: Merge Audio with Video
- Tool: FFmpeg v6.0 merges Arabic audio with original video [4].
- Output: Dubbed MP4 stored in /media/videos/ [9].

4.3.9 Step 9: Deliver Dubbed Video
- Implementation: Video URL returned via `/tts-api/generate-dubbed-video/<video_id>/` or web UI [6].
- Output: Downloadable MP4, summary, keywords, and chatbot access [10].

4.4 Testing and Validation

Testing ensured system reliability and performance [10].

- Unit Tests: Covered `STT.py`, `LLM_Online.py`, `Sayyid_work_TTS.py` using pytest 7.4.0 (95% code coverage) [11, 7, 4].
- Integration Tests: Validated pipeline end-to-end with 50 test videos (10–20 min) [10].
- User Testing: Conducted with 20 students and 5 educators; 90% rated UI as “easy to use” [10].
- Performance: Achieved 2–5 min processing for 10-min videos (i5-10400, 8GB RAM) [10].
- Reliability: 95% success rate for valid URLs, tested on 100 videos [10].

4.5 Challenges and Solutions

- Challenge: Groq API rate limits (50 requests/min) caused delays [7].
  - Solution: Implemented queue system with 5s retry intervals [7, 10].
- Challenge: Audio-video timing mismatches (±10% in 5% of cases) [4].
  - Solution: Added timing check in `Sayyid_work_TTS.py` with audio stretching [4].
- Challenge: Large video files (>1GB) slowed processing [3].
  - Solution: Limited videos to 2 hours, optimized FFmpeg parameters [3, 10].

The implementation delivers a robust system, meeting Jordanian educational needs [5].
